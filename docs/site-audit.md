## 0. 報告を受けた2件の調査結果（最優先）

### 0-1. 「GitHubに上げているのに変更が反映されない」 — 重要度：高（原因特定済み）

**原因：最新の日記コミット（807e096「Update index.html」2026-11-21、Diary「バーストアイ」）が `main` ではなく `fable-audit` ブランチに入っていた。**

- GitHub Pages は `main` ブランチを公開している。
- 前回の作業で `fable-audit` ブランチを作り、手元の作業コピーがそのブランチに切り替わったままになっていた。そのため、GitHub Desktop で行った Commit / Push が `fable-audit` 側に入り、`origin/fable-audit` に公開されていた。
- 公開サイトの Diary の先頭記事が「GitHubに移行」（＝`main` の内容）であることをブラウザで確認済み。

**副次要因（原因ではないが注意点）**
- GitHub Pages の応答は `Cache-Control: max-age=600`。Push して Pages のビルドが終わったあとも、ブラウザ側では最大10分ほど古いページが表示されることがある（強制再読み込みで解消）。
- Pages のビルド状況は、リポジトリの「Actions」タブで確認できる。

**対処**：最終まとめ（作業者からの報告）を参照。手元の `main` をこの日記コミットまで進めてあるので、GitHub Desktop で `main` に切り替えて Push すれば公開される。今後は Commit 前に GitHub Desktop 上部の「Current branch」が `main` になっているか確認する。

### 0-2. 「Essay などのページに入ると、一番下に飛ぶ」 — 重要度：高 — 対応：済（3bef614）

**原因：一部の YouTube 埋め込み（iframe）が読み込み時にフォーカスを奪い、ブラウザがその iframe の位置まで自動スクロールしていた。**

公開中サイトで再現を確認（読み込み4〜5秒後の状態）：

| ページ | スクロール位置 | フォーカスを奪った埋め込み |
|---|---|---|
| essay/diary | 78,852px / 79,620px（ほぼ最下部） | youtube.com/embed/11d5RLrotHg |
| essay/music | 20,017px | youtube.com/embed/x9u6M5Ydvk0 |
| essay/archive/2025 | 11,467px | youtube.com/embed/45QuCjxYq-s |
| movie / songwriting / kizai | 0（再現せず） | — |

**最初の修正（3bef614）では直らなかった**：全 iframe（57個）に `loading="lazy"` を付けたが、公開後も Diary で最下部へ飛ぶことを確認した。画面外の埋め込みも読み込み直後（約0.4秒）に一斉に読み込まれており、遅延読込だけではフォーカスの横取りを防げない。修正前の検証は、ページを別の iframe の中に入れて読み込む方法で行っていた。その条件ではそもそも現象が起きないため、検証として成り立っていなかった。`loading="lazy"` は表示速度の改善として残している。

**再修正（2026-11-21）**：`main.js` に `initIframeFocusGuard()` を追加した（約20行）。閲覧者がまだクリック・キー入力・スクロールをしていない間に、フォーカスが iframe に移ったことで起きたスクロールだけを元の位置に戻す。閲覧者が一度でも操作したあとは何もしない。目次リンク（`#article-N`）で開いた場合は、その記事の位置に戻す。

- JavaScript を追加した理由：埋め込みの中身（YouTube 側のスクリプト）が起こす現象で、HTML の属性だけでは確実に防げないため。この20行で、今後追加する埋め込みにも自動で効く。
- 補足：この現象は、ページを開いたウィンドウにフォーカスがあるとき（＝普通にリンクをクリックして開いたとき）に起きる。作業環境のブラウザではウィンドウのフォーカスを制御できず、公開後の動作確認が必要。
- 静的な代替案（未実装）：YouTube の iframe を、サムネイル画像と動画へのリンクに置き換える。JavaScript は不要になるが、ページ内での再生はできなくなる。

## 4. 静的サイトの方針に沿った機能候補

| 候補 | 必要性 | 静的方針との整合 | 実装コスト | 推奨 |
|---|---|---|---|---|
| **R1. meta description / OGP / title にサイト名** | 中：SNS 共有時の見え方と検索結果が改善 | ◎ HTML の head に書くだけ。JS 不要 | 小〜中（67ファイルの head に5〜7行。スクリプトで一括挿入可） | ◎ |
| **R2. favicon** | 中：タブとブックマークでサイトが識別できる | ◎ 画像ファイル1つと link タグ1行 | 小 | ◎ |

### 仮定・前提
- 公開ブランチは `main` / ルート（ユーザーとのやりとりで確認済みの設定）。
- 「Essay などに入ると一番下に飛ぶ」は、記事の多い Essay 配下のページ（Diary、Music など）での現象と解釈した。Essay トップ（essay/index.html）自体は短いページで、埋め込みもない。
- 外部サービス（postimg / YouTube / SoundCloud）は今後も使い続ける前提。
